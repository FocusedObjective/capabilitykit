AI can generate code quickly. The harder problem is making sure it builds the right thing.

CapabilityKit helps teams define product capabilities in a structured, human-readable format that AI agents can understand, implement, validate, and evolve. Instead of managing a backlog of disconnected stories, teams manage a growing map of product capabilities.

The problem

AI coding makes delivery faster. It also makes intent easier to lose.

Modern AI coding tools are powerful, but they often work from vague prompts, scattered tickets, outdated docs, and incomplete context.

That creates a new kind of software risk:

  • Requirements now live in prompts instead of tickets, then drift into stale specs and plans.
  • As the codebase grows, it gets harder to verify that new and existing features still fulfill capabilities.
  • Humans can verify capabilities against intent, but intent is often lost after prompting and implementation.
  • In PR reviews, teams have to tease out how capabilities have grown, shrunk, or changed.

What it is

A capability language for AI-native engineering.

CapabilityKit lets you describe product capabilities as structured files inside your codebase. Each file captures intent, behavior, actors, flows, constraints, interfaces, and verification expectations for a part of your product.

Product intent

Keep the product goal close to the implementation, where it can influence what gets built.

Agent instructions

Compile capability definitions into consistent context for coding agents and generators.

Verification gaps

Make missing tests, unclear interfaces, and weak acceptance criteria visible early.

Capability discovery

Give humans and agents a map of what the product can do and what it enables next.

Core positioning

From backlog of stories to backlog of capabilities.

Traditional backlogs describe work to be done. CapabilityKit describes what the product is becoming.

A story might say:

As a user, I want to upload a document so I can summarize it.

A capability defines:

  • Who can use document upload.
  • What inputs are allowed.
  • What states, outcomes, and edge cases exist.
  • What services or packages are expected.
  • What interfaces AI agents can call.
  • What must be verified.

For product managers

Give AI agents better product intent.

Define capabilities at the right level of detail, then let developers and AI agents elaborate them into working software.

  • A clearer map of what the product can do.
  • Less dependence on fragile ticket descriptions.
  • Better visibility into gaps, risks, and missing verification.
  • A capability backlog that evolves with the product.

For developers

Give AI coding tools better context.

Turn product intent into structured engineering context that AI agents can use without inferring architecture from scattered files.

  • A repo-native .capabilities folder.
  • CLI commands to create, compile, and validate capabilities.
  • Warnings for unclear interfaces or weak verification.
  • Support for implementation packages such as AWS Amplify Gen 2 and Convex.

How it works

Your coding agent should work from capabilities, not vague prompts.

1

Describe a capability

Create a capability file with actors, behavior, flows, constraints, events, interfaces, and verification expectations.

2

Compile capability context

Compile definitions into structured context that AI agents, code generators, and validation tools can use.

3

Generate or change code

Use Codex, Cursor-style agents, GitHub Copilot, Claude Code, or custom internal agent workflows.

4

Validate what changed

Ask whether behavior is implemented, edge cases are described, interfaces are clear, and tests are missing.

Verification

Verification is a first-class part of the language.

AI-native engineering needs more than code generation. It needs continuous verification. CapabilityKit treats errors and warnings as signals of missing product or engineering intent.

Automated tests Manual review steps Acceptance examples Edge cases Security constraints Performance expectations Data handling rules Integration checks Known gaps

Agentic workflows

Designed for agents that plan, implement, test, and inspect.

Each capability exposes structured intent an agentic framework can use to suggest new capabilities, identify missing details, generate plans, create code, generate tests, detect drift, and find verification gaps.

Architecture

Bring structure without forcing one architecture.

CapabilityKit is not a framework that owns your whole application. It is a capability layer that can sit inside existing apps, greenfield projects, monoliths, modular apps, serverless apps, and AI-generated prototypes.

Why it is different

Not UML. Not stories. Not another backlog tool.

Traditional modeling tools often failed because they were separate from delivery. CapabilityKit is designed to be part of delivery.

Example capability

A shared understanding of what needs to exist.

Capability
AI Document Summary
Intent
Let a workspace user upload a document and receive a useful summary.
Actors
Workspace user, admin, AI summarization service.
Inputs
PDF, DOCX, text file.
Behavior
Validate file, extract text, summarize content, store result, show status.
Constraints
File size limits, workspace permissions, token cost limits.
Interfaces
Upload service, document parser, LLM provider, usage meter.
Verification
Upload tests, permission tests, unsupported file tests, summary quality review, cost checks.
